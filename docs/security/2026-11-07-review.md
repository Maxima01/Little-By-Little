# Security and application/server connection review — 2026-11-07

<!-- Feature: record the reviewed boundaries, concrete fixes, evidence and deployment limits. -->
Scope: optional Supabase authentication and workspace sync, the Node web host, desktop trust checks, manuscript HTML sanitization, dependency metadata and the connected database's security metadata. Synced references and pre-existing legal-policy edits were left untouched.

## Findings and implemented fixes

1. **P2 — Sync preferences duplicated the manuscript and could exhaust browser storage.** `cloudFingerprint` previously returned the entire canonical workspace. `useCloudSync` persisted that string through AsyncStorage, which uses localStorage on web, while the durable manuscript uses IndexedDB. A workspace can therefore save locally and reach the cloud but fail to record its acknowledged baseline. Preferences now contain a 71-character SHA-256 fingerprint. Legacy canonical fingerprints are converted without losing the approved login, paused state or conflict baseline, and rewritten on load. The existing locked `@noble/hashes` 2.4.0 package is now an explicit production dependency. This removes a redundant plaintext copy; it does not encrypt manuscripts. Implementation: `src/features/workspace/lib/cloudSync.ts` and `src/features/workspace/hooks/useCloudSync.ts`.

2. **P2 — Request deadlines stopped at the response headers.** The original transport cleared its timer when `fetch()` resolved, before the SDK consumed the body. A stalled body could leave sync busy and prevent subsequent work. The new transport enforces the deadline through body completion, preserves caller cancellation (including a Request object's signal), checks provider origins, rejects browser redirects, omits cookies, disables caching and limits response bytes. Native buffered responses have the same deadline and a size check before SDK parsing; their transport can allocate the body before that check. No automatic write retries were added. Implementation: `src/features/workspace/lib/cloudFetch.ts` and `supabase.ts`. The distinction between receiving headers and consuming a body is documented in [AbortSignal's fetch examples](https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal#examples).

3. **P2 — Native login refresh depended on the manuscript-sync switch.** Pausing sync removed the AppState handler that restarted token refresh after backgrounding. Refresh now has its own lifecycle subscription, applies the initial app state, and cleans up on unmount. Background cloud polls also skip hidden apps and browsers known to be offline. Implementation: `src/features/workspace/lib/cloudSessionLifecycle.ts` and `src/features/workspace/hooks/useCloudSync.ts`. This follows [Supabase's native foreground-refresh guidance](https://supabase.com/docs/reference/javascript/auth-stopautorefresh).

4. **P2 — Reads lacked the rollback-preference protection already present for writes.** If PostgREST is configured to honor caller-selected transaction rollback, a caller could retrieve a workspace and discard its read-quota charge. The local schema now rejects `Prefer: tx=rollback` before reading a workspace. The regression fixture verifies this alongside the existing write guard. This is conditional on provider transaction configuration; the review did not establish that production honors rollback preferences. Implementation: `supabase/schema.sql` and `supabase/security-check.sql`.
